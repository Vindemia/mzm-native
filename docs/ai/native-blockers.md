## Dette LP64 — fonctions implicitement déclarées

`-std=gnu89` restaure le style K&R permissif de l'agbcc (avertissement au lieu d'erreur), mais chaque fonction appelée sans déclaration préalable est alors supposée retourner `int` par le compilateur. En LP64 (x86_64, `sizeof(void*) == 8`), si la fonction retourne en réalité un pointeur, la valeur réelle (64 bits) est tronquée à 32 bits à l'endroit de l'appel implicite. Aucun diagnostic, aucun crash immédiat — juste une valeur silencieusement fausse. C'est une mine pour le jalon 2 (link + exécution), pas pour le jalon 1 (compilation seule, où la valeur n'est jamais utilisée).

**Mesure** : compilation de `src/` avec `-std=gnu89 -Wimplicit-function-declaration` (avertissement, sans le neutraliser). **1170 sites**, **309 fonctions distinctes** implicitement déclarées quelque part dans `src/`. Chaque nom a été recherché dans `include/` et `src/` pour retrouver son vrai prototype (déclaration réelle ou définition) et vérifier si le type de retour contient un `*`.

**Résultat de l'audit pointeur** :

| | Compte |
|---|---|
| Fonctions implicitement déclarées (dédoublonnées) | 309 |
| — dont retour **pointeur confirmé** (dangereux en LP64) | **1** |
| — dont retour non-pointeur (safe) | 307 |
| — dont prototype introuvable dans `include/`/`src/` (asm-only) | 1 |

### La fonction dangereuse

**`SramWriteChecked`** — prototype réel `u8* SramWriteChecked(u8* src, u8* dest, u32 size);` (`include/sram/sram.h:9`, définie `src/sram/sram.c:76`). Appelée sans `#include "sram/sram.h"` dans **`src/save_file.c`** (lignes 890, 901) et employée aussi dans `src/sram_misc.c` (celui-ci inclut correctement le header — pas de risque à cet appel-là). Dans `save_file.c`, le retour est utilisé en contexte booléen (`if (SramWriteChecked(...))`) : au jalon 2, la troncature 64→32 bits pourrait faire lire un pointeur non-nul tronqué à zéro (poids forts perdus), inversant silencieusement la condition. **Correctif jalon 2** : ajouter `#include "sram/sram.h"` en tête de `src/save_file.c` — pas fait ici, hors périmètre jalon 1 (aucune modification de `src/save_file.c`).

### Cas résolu (faux positif)

`CallGetNoteFrequency` n'a aucun prototype C nulle part (implémentée uniquement en assembleur, `asm/soundcode.s`) ; le commentaire source (`asm/soundcode.s:563`) documente sa signature réelle : `s32 CallGetNoteFrequency(s32, u32)` — pas un pointeur, sans danger.
